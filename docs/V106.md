# V106 — NDS nạp/chạm/thoát/vào lại

Workflow `NDS loading and reentry (V106)` dùng chương trình NDS ARM9/ARM7 do script tự sinh: bật LCD, ghi màu cam vào framebuffer, lặp. Không tải game, BIOS, firmware hoặc logo thương mại. Chỉ tải lõi từ URL `melondsds` trong config; xác minh ELF x86_64 và ghi SHA-256 vào evidence. Builtin system files của lõi giữ nguyên từ config.

CI chạy unit trên config/ABI sản phẩm trước. Sau đó tạo config debug cục bộ, tắt crash gửi mạng, dựng bridge libretrodroid x86_64 trong checkout tạm và gói APK debug. Không sửa cấu hình sản phẩm, ABI phát hành, phiên bản hay phát hành engine pack. HTTP localhost là server fixture chỉ trong APK CI.

Flow Maestro chạm màn hình đang tải lõi (server để cửa sổ tải 40 giây), bắt buộc màn tải còn hiện sau chạm; đợi first frame và kiểm ảnh có màu framebuffer thật. Maestro mở menu tự ẩn → Thoát game; xác minh tiến trình kết thúc, mở lại cùng ROM, đợi first frame. Chỉ một request lõi được phép, file lõi không thay mtime/size. Crash/ANR làm đỏ; không skip hoặc suy game đã chạy từ PID.

Artifact chỉ ảnh/log/JSON metadata, không ROM/engine. Kết quả CI: [CHƯA KIỂM]. Flow không chứng minh mọi thao tác chạm trong cửa sổ JNI init hoặc tốc độ máy thật; V97 có test đơn vị readiness/cancel riêng.

**3DS đang kẹt:** gói Azahar và core citra trong config chỉ ARM64; emulator CI x86_64 không nạp được. Đã hỏi PM #119 chọn dựng engine x86 test-only hay dùng ARM Test Lab. Không dùng UI giả làm bằng chứng chạy 3DS, chưa tuyên bố hoàn tất V106.
